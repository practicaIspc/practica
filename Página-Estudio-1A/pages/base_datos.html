Concepto de Base de Datos y Diseño

Una base de datos es un conjunto organizado de información que permite almacenar, gestionar y recuperar datos de manera eficiente. Su diseño implica definir la estructura, relaciones y restricciones para garantizar la integridad y optimización del almacenamiento

Tipos de Datos

  • Numéricos: Enteros, decimales.
  • Texto: Cadenas de caracteres.
  • Fecha y hora: Para almacenar información temporal.
  • Booleanos: Verdadero/Falso.
  • Objetos y multimedia: Imágenes, videos, documentos

Modelo Entidad Relación (ER)

El Modelo Entidad Relación (ER) es una técnica de modelado de datos que representa la estructura lógica de una base de datos. Se basa en entidades, atributos y relaciones entre ellas. Las entidades son objetos o conceptos del mundo real, los atributos son las propiedades de las entidades y las relaciones describen cómo interactúan las entidades entre sí.

Modelo Relacional

El Modelo Relacional es un enfoque para organizar datos en tablas (o relaciones) que se relacionan entre sí. Cada tabla tiene filas (tuplas) y columnas (atributos). Las claves primarias identifican de manera única cada fila, mientras que las claves foráneas establecen relaciones entre tablas. Este modelo permite realizar consultas complejas y garantiza la integridad de los datos.

Transformación de Modelo ER a Relacional

La transformación de un modelo ER a un modelo relacional implica convertir entidades y relaciones en tablas. Las entidades se convierten en tablas, los atributos se convierten en columnas y las relaciones se representan mediante claves foráneas. Este proceso asegura que la estructura de la base de datos sea coherente y eficiente para su uso.

Ejemplo de Transformación

Supongamos que tenemos un modelo ER con dos entidades: "Cliente" y "Pedido". La entidad "Cliente" tiene atributos como "ID_Cliente", "Nombre" y "Email". La entidad "Pedido" tiene atributos como "ID_Pedido", "Fecha" y "ID_Cliente" (clave foránea que referencia a la entidad Cliente). Al transformar a un modelo relacional, tendríamos dos tablas: "Clientes" y "Pedidos", donde la tabla "Pedidos" tendría una columna "ID_Cliente" que establece la relación entre ambas tablas.

Ejemplo de Diagrama Entidad Relación (DER)

Un Diagrama Entidad Relación (DER) es una representación gráfica del modelo ER. En este diagrama, las entidades se representan como rectángulos, los atributos como óvalos y las relaciones como rombos. Por ejemplo, en un DER para el modelo de "Cliente" y "Pedido", tendríamos un rectángulo para "Cliente" con sus atributos conectados a él y otro rectángulo para "Pedido" con su relación hacia "Cliente".

Ejemplo de Diagrama Relacional

Un diagrama relacional muestra la estructura de las tablas en un modelo relacional. En este diagrama, cada tabla se representa como un rectángulo con sus columnas enumeradas dentro. Por ejemplo, tendríamos un rectángulo para la tabla "Clientes" con las columnas "ID_Cliente", "Nombre" y "Email", y otro rectángulo para la tabla "Pedidos" con las columnas "ID_Pedido", "Fecha" y "ID_Cliente". Las relaciones entre tablas se indican mediante líneas que conectan las claves foráneas con las claves primarias correspondientes.

Ejemplo de Esquema Relacional

Un esquema relacional es una representación formal de la estructura de una base de datos relacional. Incluye la definición de tablas, columnas, tipos de datos y restricciones. Por ejemplo, el esquema relacional para las tablas "Clientes" y "Pedidos" podría definirse como:

CREATE TABLE Clientes (
    ID_Cliente INT PRIMARY KEY,
    Nombre VARCHAR(50),
    Email VARCHAR(100)
);
CREATE TABLE Pedidos (
    ID_Pedido INT PRIMARY KEY,
    Fecha DATE,
    ID_Cliente INT,
    FOREIGN KEY (ID_Cliente) REFERENCES Clientes(ID_Cliente)
);

Este esquema define las tablas, sus columnas y las relaciones entre ellas, asegurando la integridad referencial.

Ejemplo de Consulta SQL

Una consulta SQL es una instrucción utilizada para interactuar con una base de datos relacional. Por ejemplo, para obtener todos los pedidos realizados por un cliente específico, podríamos usar la siguiente consulta:

SELECT * FROM Pedidos
WHERE ID_Cliente = 1;

Esta consulta selecciona todos los registros de la tabla "Pedidos" donde el "ID_Cliente" es igual a 1, devolviendo así todos los pedidos realizados por ese cliente.

Ejemplo de Normalización

La normalización es el proceso de organizar los datos en una base de datos para reducir la redundancia y mejorar la integridad. Por ejemplo, si tenemos una tabla "Clientes" con información duplicada, podríamos dividirla en dos tablas: "Clientes" y "Direcciones", donde "Clientes" contenga información básica y "Direcciones" contenga detalles de dirección. Esto ayuda a evitar la duplicación de datos y mejora la eficiencia del almacenamiento.

Ejemplo de Integridad Referencial

La integridad referencial es una propiedad que garantiza que las relaciones entre tablas se mantengan consistentes. Por ejemplo, si tenemos una tabla "Pedidos" con una clave foránea "ID_Cliente" que referencia a la tabla "Clientes", no se permitirá insertar un pedido con un "ID_Cliente" que no exista en la tabla "Clientes". Esto asegura que todas las relaciones sean válidas y evita datos huérfanos.

Ejemplo de Restricciones

Las restricciones son reglas que se aplican a los datos en una base de datos para garantizar su validez. Por ejemplo, podríamos establecer una restricción de unicidad en la columna "Email" de la tabla "Clientes" para asegurarnos de que no haya dos clientes con el mismo correo electrónico. Esto ayuda a mantener la integridad de los datos y evita duplicaciones no deseadas.

Ejemplo de Índices

Los índices son estructuras que mejoran el rendimiento de las consultas en una base de datos. Por ejemplo, si tenemos una tabla "Clientes" y realizamos consultas frecuentes basadas en la columna "Nombre", podríamos crear un índice en esa columna para acelerar las búsquedas. Esto permite que la base de datos encuentre rápidamente los registros relevantes sin tener que escanear toda la tabla.

Noción de Registro

Un registro es una fila dentro de una tabla de base de datos que contiene información sobre una entidad específica. Cada registro está compuesto por varios campos, que representan atributos de la entidad.

Concepto de Archivo

Un archivo en bases de datos es un conjunto de registros almacenados en un sistema de archivos. Puede ser estructurado (como una tabla en una base de datos relacional) o no estructurado (como documentos JSON o XML).

Operaciones Relacionadas con el Uso de Ficheros en Bases de Datos

  • Inserción: Agregar nuevos datos.
  • Actualización: Modificar registros existentes.
  • Eliminación: Borrar datos innecesarios.
  • Consulta: Recuperar información mediante SQL.

Cardinalidad

La cardinalidad en bases de datos define la cantidad de relaciones posibles entre entidades. Se clasifica en:

  • Uno a Uno (1:1): Cada registro de una tabla se relaciona con un solo registro de otra tabla.
  • Uno a Muchos (1:N): Un registro de una tabla puede relacionarse con múltiples registros de otra tabla.
  • Muchos a Muchos (M:N): Varios registros de una tabla pueden relacionarse con varios registros de otra tabla.

Definición formal de relación

Una relación en bases de datos es la asociación entre dos o más entidades. Se representa mediante una tabla que contiene claves foráneas para establecer vínculos entre registros.

Propiedades de las tablas (o relaciones)

Las tablas en bases de datos tienen propiedades clave:

  • Estructura definida: Columnas con tipos de datos específicos.
  • Integridad referencial: Relaciones entre tablas bien establecidas.
  • Consistencia: Datos organizados sin redundancia.

Tipos de tablas

Las bases de datos pueden contener distintos tipos de tablas:

  • Tablas de datos: Almacenan información principal.
  • Tablas de relación: Conectan entidades en relaciones M:N.
  • Tablas temporales: Usadas para almacenamiento transitorio.

Claves

Las claves identifican registros de manera única:

  • Clave primaria: Identificador único de cada fila.
  • Clave foránea: Referencia a una clave primaria de otra tabla.
  • Clave compuesta: Formada por múltiples columnas.

Nulos

Un valor nulo indica ausencia de datos en una columna. Puede ser útil para representar información desconocida o no aplicable, pero debe manejarse con cuidado para evitar inconsistencias.

Restricciones

Las restricciones en bases de datos son reglas que garantizan la integridad y validez de los datos almacenados. Se utilizan para evitar errores, duplicaciones o inconsistencias en la información.

Existen varias restricciones comunes en bases de datos:

  • NOT NULL: Evita valores vacíos.
  • UNIQUE: Asegura que los valores sean únicos.
  • CHECK: Valida que los datos cumplan condiciones específicas.
  • DEFAULT: Asigna un valor predeterminado si no se proporciona uno.
  • FOREIGN KEY: Mantiene la integridad referencial entre tablas.
  • PRIMARY KEY: Define la clave primaria de una tabla.
  • INDEX: Mejora el rendimiento de consultas.
  • TRIGGER: Ejecuta acciones automáticas ante eventos específicos.
  • VIEW: Crea una vista virtual de los datos.
  • STORED PROCEDURE: Almacena procedimientos para realizar operaciones complejas.
  • TRANSACTION: Agrupa operaciones para garantizar la atomicidad.
  • ROLLBACK: Revierte cambios en caso de error.
  • COMMIT: Confirma cambios realizados en una transacción.
  • GRANT: Otorga permisos a usuarios.
  • REVOKE: Revoca permisos otorgados.
  • ALTER: Modifica la estructura de una tabla.
  • DROP: Elimina una tabla o base de datos.
  • CREATE: Crea una nueva tabla o base de datos.
